# 指スマの仕様

更新日: 2026-09-23

## 操作の流れ

- 設置先はユーザー指定のスレッド `1552248958443716688`（指スマパネル）。同日の追加依頼で実装・設置を許可。
- 初期ボタンは「プレイ開始」「ルール説明」「残高確認」。
- プレイ開始後に「1人プレイ」「2人プレイ」を選ぶ。
- 1人プレイはCPU対戦。2人プレイは双方がUser Selectでお互いを選ぶと成立する。
- 待機中は「対戦に戻る」で確認でき、「対戦希望を取り消す」でキャンセルできる。
- 成立時はスレッドに対戦画面を投稿し、参加者は「入力・進行を確認」から本人だけに見える画面を開く。
- 宣言役は自分の上げる本数と合計の予想を1回の選択で確定する。相手は上げる本数を選ぶ。
- 両者の入力が揃うまで、相手の入力は公開しない。確定済み入力は変更できない。

## ルール

ユーザー確認済みの基本ルール:

- 両者とも手を2本使って開始する。
- 宣言役を交互に交代し、両者が上げた親指の合計を当てる。
- 当てた人は手を1本抜き、先に0本になった人の勝ち。

初期実装の運用:

- 最初の宣言役はランダム。
- 上げられる本数は0〜自分の残りの手。予想は0〜両者の残りの手の合計。
- CPUは各ラウンドの開始時にランダムで入力を確定し、人間の入力後に変更しない。
- 入力期限はラウンド開始から2分。期限切れは勝敗なしで終了する。
- 対戦希望は5分有効。進行中の対戦は1人1つ。確定した対戦を途中終了する場合は確認画面を経て降参し、相手の勝ちになる。
- 賭け金・報酬は設けない。

## 残高確認

既存LIAとの連携判断は保留。既定の `BALANCE_MODE=unavailable` は準備中と表示する。
`BALANCE_MODE=lia` を明示設定した場合だけ、同じDBの `accounts.wallet` を本人の `user_id` で取得し表示する。口座を作成・更新しない。

## 構成と永続化

- TypeScript / discord.js v14 / Railway / MySQL。
- 対象サーバーの `GUILD_ID` はRailwayの環境変数から取得する。
- RailwayプロジェクトはLEVELIA、新しい独立サービスはLEVELIA_GAME。リポジトリも既存Botと分離する。
- `levelia_game_rooms` の1行をサーバー・スレッド単位でロックし、対戦希望・ゲーム・非公開入力をJSONとして原子的に保存する。
- 再起動後も期限内のゲームは復帰可能。古いラウンド、二重入力、第三者操作、別サーバー・スレッドでの操作を拒否する。
- 終了したゲームは直近50件のみ保持する。対戦中のゲーム上限は1スレッド100件。
- 対戦の確定と公開メッセージ送信は分離する。送信失敗で対戦を再実行せず、30秒ごとに再送・期限切れ表示を処理する。
- 公開メッセージ更新も部屋のロック内で最新状態を取得する。投稿ID保存前に停止した場合は直近100件のメッセージからゲームIDを照合して復旧を試みる。
- インタラクションにはDB/APIアクセス前にephemeralの `deferReply` を行う。
- Activitiesは未実装。
