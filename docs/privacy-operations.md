# 公開前の確認とデータ対応

2026-10-02時点。利用規約・プライバシーポリシーと実装を照合するための運営用メモ。
これは法的適合性やセキュリティ全般の保証ではない。

## 文面・実装で確認した範囲

- 運営者はシロ、問い合わせ先はDiscordの `sh1r0_0921` へのDM。
- LIAは現金購入・換金・景品交換を提供しないサーバー内通貨として案内する。運用でもこの条件を維持する。
- Activityの認証権限は `identify`。認可コードとアクセストークンはDB・ブラウザの永続ストレージへ保存しない。
- ゲームの専用テーブルに加え、既存の `accounts` と `actions` を利用する。Activityだけのデータとして削除範囲を説明しない。
- 最高連勝数はゲーム記録から集計する。クライアントが送った最高記録を保存しない。
- アプリ側の例外ログでは任意のエラーオブジェクト、SQL、リモートレスポンス本文を記録せず、固定文言と数値のエラー情報に限定する。
- アプリコードでIPアドレスを独自に収集・保存する処理は確認されていない。これはDiscordや配信基盤のログが存在しないという意味ではない。
- 期限切れの手札への予想・手動精算・heartbeatによる延命を拒否する。ゲームの期限・自動精算仕様は変更しない。

## 公開前に残る確認

- サーバー退出後も上記ユーザー名を検索できるか、DMを送信できるかを別アカウントで確認する。DMが届かない場合は実際に受信できる代替窓口を用意する。
- Railway・MySQL・Discordチームのアクセス権を確認する。不要なメンバー・公開経路がないこと、必要な認証保護が有効なことを確認する。
- DB保存時の暗号化、接続経路、バックアップの有無・保存期間・復元権限を確認する。未確認の安全対策をポリシーで断定しない。
- RailwayのHTTPログと実行ログの記録項目・保存期間・閲覧権限を確認する。過去ログに機密情報が含まれていれば、削除可否と認証情報の失効・更新を判断する。
- 下記の削除手順を隔離したデータで検証し、担当者が実行できる状態にする。手順書を置くだけでは削除対応の準備完了とはしない。
- 公開した規約・ポリシーのURLを認証なしで開けることを確認し、Discord Developer Portalへ登録する。所有者の本人確認は別途必要。

## 確認・訂正・削除依頼の手順

1. 原則、対象のDiscordアカウントからDMを受け付ける。対象ID、依頼日時、希望する対応を必要な範囲で記録する。パスワード・トークン・不要な身分証は要求しない。
2. 本人確認後、対象IDに関連するゲーム記録、操作記録、台帳、共通取引履歴、問い合わせ履歴、ログ、バックアップを洗い出す。共有口座や相手側履歴への影響も確認する。
3. 進行中のゲームや同時書き込みを残したまま削除しない。対象範囲・利用できなくなる機能を説明し、既存Botの管理手順と調整する。アプリ解除はDB削除の代わりにならない。
4. 専用テーブルは外部キーがあるため、対象ユーザーの `levelia_game_high_low_commands` と `levelia_game_high_low_ledger`、次に `levelia_game_high_low_hands` の順に処理する設計を検証する。実行前後で件数・対象ID・残高を照合する。
5. `actions` は送信元・送信先双方のIDとコメントを確認する。`accounts` や他のBotの記録を一括削除しない。共通データへの対応は影響範囲と権限を確認した個別手順が必要。
6. バックアップの削除可否・失効時期を確認する。復元によって削除済みデータを通常利用に戻さない手順を用意する。削除対象のコピーを無期限に残さない。
7. 完了範囲と未完了範囲を利用者へ伝える。法令上保存が必要な情報がある場合は具体的な理由を示す。「運営に便利」という理由だけで削除要請を無期限に保留しない。

本番の削除SQL・自動削除機能は、この点検では実行・追加していない。共有システムを含む削除対応と保存期間の確認は未完了。

## 漏えい等が疑われる場合

アクセスを封じ、影響する認証情報を失効・更新し、必要最小限の調査記録で対象と期間を特定する。Discordの開発者規約および適用法令に従い、Discord・利用者への通知を判断する。原因の解消と再発防止を確認するまで、影響する機能を再開しない。
